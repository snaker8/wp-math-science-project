> 작성 2026-09-06 · 근거: `docs/benchmark/matholic/08-type-analysis.md`(유형 칸의 「중요」 배지 실측) · 운영 DB 실측
> 상태: **설계서.** 데이터 재료는 있다(아래 §1). 코드 착수 전 대표 확인 — 「중요」의 정의를 우리 데이터로 어떻게 정할지가 결정 사항.

## 0. 매쓰홀릭의 「중요 유형」

유형분석 판의 칸에 「중요」 배지가 붙는다. 매쓰홀릭은 전국 내신 출제 데이터로 **내신 빈출 유형**을 표시한다(08 §4).
우리는 그 데이터가 없다 — 대신 **우리 학원이 자산화한 학교기출 시험지**가 있다. 그게 우리 정의의 재료다.

## 1. 재료 (2026-09-06 실측)

| 재료 | 위치 | 상태 |
|---|---|---|
| 학교기출 시험지 | `exams` (클라우드 「학교기출」 폴더·출처 버튼) · 제목에 학교·학년·학기·중간/기말 | 47교 · 제목 파싱 147/195 (클라우드 패싯 작업) |
| 문제 → 유형 | `classifications.type_code`(수학비서 depth5) | 분류 23% (배치 진행 중) |
| 문제 출처 | `problems.source_name` (예 `25-3-1-F 해강중 수학`, `2025학년 주례여고 수1 1학기 중간`) | 자유 텍스트, 학교명 포함 |

→ **「어느 학교 몇 학년 몇 학기 시험에 이 유형이 몇 번 나왔나」** 를 셀 수 있다. 분류가 붙는 만큼 정확해진다.

## 2. 정의 (제안)

```
출제 빈도(type, scope) = 그 유형 문제가 들어 있는 학교기출 시험지 수 / scope 안 학교기출 시험지 수
  scope = 과정(중3-1) 전체   → 「내신 빈출」  : 시험지 30% 이상에 등장
  scope = 특정 학교          → 「이 학교 빈출」: 그 학교 시험지 2회 이상 등장
```
- 분모는 **분류된 문제가 있는 시험지**만 (미분류 시험지는 아직 모르는 것이지 안 나온 게 아니다).
- 시험지 수로 센다(문제 수가 아니라). 한 시험지에 같은 유형 3문제는 1회.
- 학교는 시험지 제목 파서 `src/lib/exams/parse-exam-title.ts`(클라우드 패싯의 학교·학년·학기 추출)를 그대로 쓴다. 파싱 실패분은 과정 scope 에만 들어간다.

## 3. 어디에 보이나

| 화면 | 표시 |
|---|---|
| 유형분석 판 칸 | 모서리 작은 「★」 또는 두꺼운 테두리 = 내신 빈출. 팝오버에 「학교기출 N/M 시험지 (xx%)」 + 학교 목록 |
| 유형분석 툴바 | 「학교」 선택(반 학생들의 학교 자동 후보) → 그 학교 빈출로 배지 전환. 「중요 유형만」 필터 |
| 코스 회차 계단 | 회차 계획 때 빈출 유형을 먼저 채운다(선택 옵션) — 매쓰홀릭 교재의 「내신빈출」 학습지 대응 |
| 과제 만들기 | 「중요 유형 과제」 = 빈출 유형 × 아직 약한 칸 |

## 4. 구현 (3단계, AI 0)

| 단계 | 내용 |
|---|---|
| K1 | `GET /api/mathsecr/key-types?subject=MS05&school=` — 서버 집계(캐시 10분). 시험지 집합 = 학교기출 폴더·출처 + 제목 파싱 학교. 반환 `{ code, exams, total, pct, schools[] }` |
| K2 | 유형분석 판 배지·팝오버·「중요 유형만」·학교 선택 (`MasteryMatrix`) |
| K3 | 코스 계단 옵션 「빈출 우선」 · 「중요 유형 과제」 (`course-ladder` 가중치 · GenerateAssignmentModal kind) |

## 5. 결정이 필요한 것

| 항목 | 제안 |
|---|---|
| 「내신 빈출」 문턱 | 과정 시험지의 30% (실측 뒤 조정 — 분류가 23% 라 지금 수치는 흔들린다) |
| 학교 scope 의 최소 표본 | 그 학교 시험지 2장 이상일 때만 「이 학교 빈출」 표시 |
| 착수 시점 | **분류 배치가 고1·중3 을 넘긴 뒤** — 그 전엔 배지가 있다 없다 한다 |
