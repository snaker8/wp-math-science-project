## 2. ❶ 소스 선택 — 우리 강점을 첫 칸에

매쓰홀릭은 13종(교재연계 3·내신수능 6·초등 1·문제은행 2·목적별 4).
우리는 **가진 것 + 강점 순서**로 6종에서 시작한다.

| 순 | 소스 | 근거 데이터 | 상태 |
|---|---|---|---|
| **1** | **우리 학원 기출** ★강점 | 학교기출 141건, 출처 100%(학교·연도·중간/기말) | 즉시 가능 |
| 2 | 유형별 | 수학비서 2,573 유형 + 분류 5,897건 | 즉시 가능 |
| 3 | 단원별 | 같은 분류 데이터 | 즉시 가능 |
| 4 | **오답(학생별)** ★루프 | 진단 items 2,746 + QR 1,658 + 숙달 3,950 | 즉시 가능 |
| 5 | 고난도·서술형 | difficulty + problems.type | 즉시 가능 |
| 6 | 시중교재 유사 | 시중교재 자산화 1건 → **축적 대상** | 데이터 쌓이는 만큼 |

   → 소스 1번을 **학교·학년·학기·중간/기말 4단 좁히기**로 만든다. 우리만의 첫 화면.

## 4. ❸ 문제 편집 — 2분할 + 교체/추가

참조: `benchmark/matholic/03-problem-edit.md`

- **좌**: 선택 문제 번호순 배열(난이도 배지·삭제·정렬). 우리 `SelectionTray` 확장
- **우**: 후보풀 탭 — `유사(기본)` / `기출` / `고난도` / `서술형` / `내 폴더`
- 각 후보에 **[교체]**(번호 유지·대체) / **[추가]**(새 문항) **두 버튼 분리** ← 우리에 없는 개념
- 유사 후보 = **①같은 유형 다른 문제(DB) + ②twin-generator 변형(숫자·조건)**
  → AI 변형은 비용 발생 → 해설 PIN 게이트와 같은 방식으로 통제 검토

## 5. ❹ 시험지 설정 → 인쇄 라인 인계

- 제목(자동 제안: 범위+과정+시각), **기간(제출기간)**, 서술형 시작번호, **분할생성(N문제씩)**

- ★ 인쇄·조판·한글 출력은 **손대지 않는다** (이미 우리가 더 강함)

## 10. 적용 기록

### S1 난이도 분포 카운터 (2026-09-07)

| 항목 | 결과 |
|---|---|
| 밴드 | `lib/class/mastery-bands` 에 **5단** 추가 — 개념 1~3 · 기본 4~5 · 실력 6~7 · 심화 8~9 · 고난도 10. 판(4단)의 심화를 한 칸 더 쪼갠 것이라 **출제와 판이 같은 말**을 쓴다. vitest 24 |
| 카운터 | `DifficultyDistribution` 를 1~10 막대 → **5단 행(라벨·막대·개수·%)** 으로. 매쓰홀릭 실측(개념14/기본14/실력22/심화18/고난도0)과 같은 형태 |
| 미분류 | 난이도 없는 문제를 **숨기지 않고 「미분류 N」으로 센다** — 분류 23% 진행 중이라 섞여 들어온다. 숨기면 분포가 사실보다 고르게 보인다 |
| 접힌 상태 | 선택 트레이 탭에 **5단 미니 막대** — 트레이를 열지 않아도 편중이 보인다 |

**남은 것 (S1 의 나머지 = 출제 구성 패널)** — 유형별 문제수(1~4개) · 답안 형태(전체/객관식/주관식) · 최대 문제수 · 중복 출제 방지 · 대표문제 우선. 카운터는 「보여주는」 절반이고 이쪽이 「맞추는」 절반이다.

**그 다음** — S2 통합 진입(`/dashboard/exam/new`, 지금 출제 화면이 6개로 흩어져 있다) · S3 2분할 편집(교체/추가) · S4 오답 소스 · S5 twin-generator 연결(AI 비용).

### 난이도 언어 통일 (2026-09-12) — 출제 라인의 1~5 척도 버그

**증상**: `/dashboard/create`(유형별 출제)가 최상·상·중·하·최하 의 **1~5 척도**였다.
우리 `classifications.difficulty` 는 **1~10** 이라, 실측 기준 **난이도 6~10 의 2,862문항(전체 분류의 28%)**이
① 배지에서 전부 '중' 으로 찍히고 ② 난이도 필터로 못 고르고 ③ 자동 배분 풀에서 아예 안 뽑혔다.

| 곳 | 전 | 후 |
|---|---|---|
| `lib/class/mastery-bands` | 5단 밴드만 있음 | `EXAM_BAND_LABELS` · `LEVELS_BY_BAND_LABEL` · `bandLabelOf()` — 출제와 판을 잇는 다리 |
| `/api/exams/available-counts` | `{'1'..'5'}` 카운트 | 5단 라벨 카운트 (`bandLabelOf`) |
| `/api/exams/generate` | `'최상'→'5'` 단일값 | 라벨 → 레벨 **묶음**, 풀은 그 범위 전체 |
| `/api/problems/search` | `difficulty` 단일 `.eq()` | `band` 파라미터 → `.in(levels)` (`difficulty` 는 백워드 호환) |
| `/dashboard/create` | 최상~최하 · 배지 1~5표 | 개념·기본·실력·심화·고난도 · 배지 `bandLabelOf(1~10)` · 미분류 표시 |

이제 출제 화면 · 유형분석 판 · 코스 회차 계단이 **같은 다섯 단어**를 쓴다. vitest 28.

### S1 출제 구성 패널 (2026-09-12)

난이도 카운터의 「보여주는」 절반에 이어 「맞추는」 절반.

| 옵션 | 구현 |
|---|---|
| **답안 형태** (전체·객관식·주관식) | `problems.answer_type` 생성 컬럼. 자동 모드 세그먼트 · 수동 검색 select. `available-counts`·`generate`·`problems/search` 세 곳 모두 필터 — **고르면 밴드별 「있는 문제 수」도 그 형태로 다시 센다**(화면 숫자와 실제로 뽑히는 문제가 어긋나면 안 된다) |
| **최대 문제수** | 10/20/25/30/50 프리셋(기본 30). 예전엔 50 이 코드에 박혀 있었다. 합계가 상한을 넘으면 호박색 경고 |

**남은 것** — 중복 출제 방지(학생 이력 대조)·대표문제 우선(usage_count)은 2차. 그 다음이 S2 통합 진입.

### ✅ 해결: 훅 순서 결함 + 과학 트랙 잠금 (2026-09-12, 대표 「과학 일단 비활성화」)

`/dashboard/create`(39건)·`/dashboard/problem-bank`(27건)이 과학 트랙 안내 카드를 **훅 선언보다 위에서 조기 return** 했다.
화면에 머문 채 트랙을 전환하면 React 가 훅 개수 불일치로 터지는 구조였다. **eslint rules-of-hooks 66건 → 0건.**

| 조치 | 내용 |
|---|---|
| 과학 잠금 | `featureFlags.SCIENCE_TRACK_DISABLED = true` → `TRACK_SPLIT_ENABLED` 가 항상 false. env 는 그대로 두어 **실수로 켜지는 것도 막는다**. 다시 켤 때 이 상수만 false |
| 스위치 일원화 | 미들웨어가 `process.env` 를 직접 읽어 클라이언트와 갈려 있었다 → `featureFlags` import 로 통일 |
| 조기 return 제거 | 두 화면에서 과학 안내 블록 삭제(잠갔으니 분기 자체가 불필요) + 미사용 `Beaker` import 정리 |

**URL 호환**: `/math/dashboard/...` 는 `(tracks)/[track]` 라우트 그룹이 그대로 있어 계속 열린다. `/dashboard/...` 직접 주소도 동작.
플래그 문서가 말하는 대로 false 가 「모든 사용자 math 단일 트랙 = 기존 운영 흐름」이다.

### S3 문제 편집 2분할 — 교체 / 추가 (2026-09-13)

매쓰홀릭에 있고 우리에게 없던 개념: **[교체]와 [추가]를 나눈다.**
한 버튼으로 뭉쳐 두면 「이걸 누르면 원래 문제가 빠지나?」를 매번 헷갈린다.
교체는 그 **자리를 대신**한다(번호 유지), 추가는 맨 뒤에 새 문항으로 붙는다.

| 조각 | 내용 |
|---|---|

### S4 오답 소스 (2026-09-14)

출제 라인에서 **「학생이 틀린 것」을 근거로** 시험지를 만든다. 메꾸기 루프의 진입로다.
취약 보충이 「약한 **유형**에서 새 문제」라면, 여기는 **틀린 그 문제**가 출발점이다 — 다른 기능이라 탭을 나눴다.

| 갈래 | 무엇 | 왜 |
|---|---|---|
| **틀린 문제 그대로** | 그 문제를 다시 풀린다 | 넘어갔는지 확인 |
| **같은 유형 새 문제** | 같은 유형(depth5)에서 난이도 가까운 순, 오답 하나당 1~3개 | 답을 외운 게 아닌지 본다 |

- `POST /api/exams/wrong-source` · `WrongSourcePanel` · 출제 화면 **오답** 탭 · 통합 진입 카드 1장.
- **AI 안 쓴다.** 채점 기록과 우리 분류만 본다 (비용 0). AI 변형은 S5.
- 유사 갈래는 그 학생들이 **이미 풀어 본 문제를 뺀다** — 새 문제라며 본 걸 주면 안 된다.
- 결과는 **전부 담긴 상태로 시작**한다(취약 보충과 같은 흐름). 교사는 빼기만 한다.
- 기본 기간은 **전체**다. 채점이 학기 단위로 몰려서 4주 기본이면 대개 빈 화면이 된다

**오답 판정은 한 곳에서만** — `lib/class/wrong-answers.ts` 로 뺐다.
오답 과제(clinic)·회차 오답유사·여기가 각자 짜고 있으면 언제든 한 곳만 고쳐져
「같은 학생인데 화면마다 오답 수가 다르다」가 된다. 마지막에 맞힌 문제 제외·자동채점 보류 제외·신원 병합이
같은 규칙으로 돈다. 오답 과제 라우트도 이 lib 를 쓰도록 옮겼다(동작 동일).

실측(2026-09-14): 남은 오답 **663건 · 학생 53명 · 문제 308개**, 그 308개 모두 유형이 붙어 있고

### S5 AI 유사문제 (2026-09-14) ★비용 발생 — 대표 승인 09-14 「소넷 5가 맞다」

후보풀 **「유사」 탭에만** 붙는다. 기출·고난도·서술형은 우리 자료로 찾는 자리다.
같은 유형에 쓸 문제가 없을 때의 **마지막 수단**이지 기본 수단이 아니다.

| 단계 | 무엇 | 비용 |
|---|---|---|
| ① 버튼 | 「AI 변형 만들기」 — 누르면 **바로 안 돈다.** 무엇을 만드는지와 단가를 먼저 보여준다 | 0 |
| ② 만들기 | AI **1회**. 원본 구조는 두고 숫자·조건만 변형 + 정답 재계산 + 풀이 | 약 35원 |

| ④ 담기 / 교체 / 버리기 | 담아야 `problems` 에 저장된다 | 0 |

**실측 1건** (원 두 개의 둘레 합, 난이도 5): 입력 863 · 출력 1,522(**생각 1,153**) · 13.4초 ≈ **35원**.
답까지 맞았다 — `r²-12r+20=0 → r=2,10 → 24π`. 다만 **토큰 추산 19원의 두 배**다.
생각 토큰이 출력의 3/4를 먹는다. 생각을 끄면 싸지지만 이 자리는 **직접 풀어 맞히는 게 전부**라 끄지 않는다.
화면에도 35원으로 적었다(추산 아닌 실측).

지킨 규율:
- **버튼 한 번에 한 건.** 배열도 배치도 자동 재시도도 없다. (분류 전체도 비용 때문에 천천히 도는 중 — 대표 09-14)

- **그림 붙은 문제는 거절한다.** 숫자를 바꾸면 그림과 어긋나는데 그림은 못 고친다.
  조용히 틀린 문제를 만드느니 안 만드는 게 낫다 (`hasFigure` 게이트, 422).
- 저장분은 **공통 풀에 안 넣는다.** 만든 학원 소유(`resolveInsertInstituteId`), `source_name='AI 변형'`,
  `ai_analysis.origin='ai-variant'` + 원본 id. 분류는 원본 것을 물려받는다(같은 유형·난이도가 이 기능의 전제).
- `window.confirm` 안 쓴다 — 2단 확인은 인라인으로. (자동화 탭이 멈춘 사고)

**설계서 S1~S6 전부 적용됨.**

### 학습지 설정 3종 — 서술형 시작번호 · 분할생성 · 기간+반 배포 (2026-09-19)
