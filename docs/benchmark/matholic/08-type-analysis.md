### ★ 모양이 두 종류다 — 사각형 vs 원형
화면 안내: **"● 모양은 AI 예측 유형 분석결과입니다."**

→ 이게 결정적이다. 진단을 조금만 해도 **매트릭스 전체가 채워진다.**

   상단 `분석 방법: AI 예측` 토글로 켜고 끈다.

## 3. ★ 칸 클릭 → 과제로 (루프의 연결점)

칸을 누르면:
1. **툴팁**에 `유형 13 · 같은 것이 있는 순열` + **대표 문제 본문**이 뜬다
   (실측: "average의 7개의 문자를 일렬로 나열할 때, 2개의 a 사이에 홀수 개의 문자가 놓이도록 나열하는 방법의 수를 구하시오.")
2. 우측 패널 `선택된 유형` 카운터가 **0 → 1**
3. **`과제 만들기` 버튼이 비활성 → 활성**

→ **약점 칸을 눌러 모은 뒤 그대로 과제로 내보낸다.** 화면을 떠나지 않는다.

우측 패널 구성:
```
선택된 유형
    1
[ 과제 만들기 ]     ← 0개면 비활성
이름전체보기  (토글)
[ 김태한 ]          ← 학생 목록. 고르면 그 학생 색으로 다시 칠함
[ 염예진 ]
```

| 교재별 매트릭스 전환 | 없음 |
| 대표 문제 미리보기 툴팁 | 없음 |

### 우리 데이터로 되는가
- **행(소단원)**: `mathsecr_types` level3 — 있다.
- **열(난이도)**: `classifications.difficulty` 1~10 — 있다. 4단계로 접으면 된다.
- **칸(유형)**: level4 세부유형 — 있다.
- **색(숙달)**: `diagnostics.student_node_status` (α/β/γ) — 있다. 63명·3,950건.
- **대표 문제**: 유형 코드로 `problems` 조회 — 있다.
- ✕ **AI 예측 채움**: 없다. 안 하면 회색이 대부분일 것 — **다만 이건 비용이 드는 기능이라 별건.**

→ **AI 예측을 빼면 나머지는 지금 데이터로 만들 수 있다.**

## 5-1. `과제 만들기` 모달 — 루프의 끝 (실측)

★ **취소만 하고 실제로 내보내지 않았다** (누르면 학생에게 과제가 나간다).

```
과제 옵션 선택

  과제명       [(2026.09.02) 1.1.2 같은 것이 있는 순열]          ← 자동 생성

  추천 과제명   (과제시작일) 출제단원  (2026.09.02) 1.1.2 …   [적용]
               출제범위             1.1.2 같은 것이 있는 순열 [적용]
               (과제시작일) 수업명   (2026.09.02) 확률과 통계… [적용]

  시작일~마감일 [2026-09-02] [17:16]  ~  [2026-09-27] [17:16]
               마지막 설정 기간  2026-08-21 00:00 ~ 2026-09-14 23:59  [적용]

  출제방식      ● 동일유형(문제 선택)   ○ 추천유형   ○ 선택유형
               "학생 모두에게 같은 유형의 같은 문제를 과제로 출제합니다.
                선택한 유형 내에서 문제를 골라서 과제로 출제합니다."

  유형 당 출제 문제수   ● 1문제   ○ 2문제

                                                    [ 다음 ]
```

### 눈여겨볼 것
- **과제명을 세 가지 방식으로 자동 제안**하고 각각 `적용` 버튼. 타이핑이 없다.
- **`마지막 설정 기간` 재사용 버튼** — 매번 날짜 찍는 수고를 없앤다. (04 문서의 학습지 설정에도 같은 패턴)
- **출제방식 3종**
  | 방식 | 뜻 |
  |---|---|
  | 동일유형(문제 선택) | 전원에게 **같은 문제**. 선택 유형 안에서 교사가 고른다 |
  | 추천유형 | 시스템이 고른다 (미확인) |
  | 선택유형 | 유형만 지정, 문제는 학생별로? (미확인) |
- **유형 당 1~2문제** — 유형 수 × 1~2 로 분량이 정해진다. 약점 10개면 10~20문항.

→ **약점 칸 클릭 → 과제 만들기 → 기간·분량만 정하면 끝.** 문제를 직접 안 고른다.
   우리 `출제` 링크는 아직 "검색 결과를 사람이 골라 담는" 단계까지다.

## 8. 단원분석 (`/ug-dashboard`) — 축이 다르다

**행 = 학생 × 열 = 소단원.** 난이도는 축에서 빼고 **필터**로 돌린다(`기본 / 실력 / 심화`).
대단원 탭(`1 경우의 수 / 2 확률 / 3 통계`)으로 범위를 좁힌다.

각 학생 행이 **2줄**이다 (숙달/미학습을 위아래로 나눈 것으로 보임 — 미확인).

→ 유형분석은 **학생 한 명을 깊게**, 단원분석은 **반 전체를 한눈에**. 같은 데이터, 다른 축.

## 9. ★ 유형이력 (`/score-history`) — 시간축. 상담용

한 학생의 **9주간 추이 꺾은선** + 그 아래 그 시점의 매트릭스.

```
        400 ┤ ●╲                                 GREEN ─── 잘하는 유형 수
            │   ╲●╲                              RED   ─── 약점
        250 ┤      ╲●╲          ╱●───●           GRAY  ─── 미학습
            │         ╲●╲    ╱●╱
        100 ┤    ╱●───●─╳●───●        ╲●───●
            │ ●╱     ╱●
          0 └─────────────────────────────────
            07/06  07/20  08/03  08/17  08/31
              8월 31일부터 이전 9주간 학습이력
```

**GRAY(미학습)가 내려가고 GREEN이 올라가는 게 한 장에 보인다.** 학부모 상담에 그대로 쓴다.

- 상단 `학생 선택` + **날짜 이동 `< >`** — 과거 시점의 매트릭스를 그대로 재현
- `보기선택: ☑이력차트 ☑유형분석` — 둘 다 켜거나 하나만
- **`흑백출력` / `출력`** — 인쇄 전제. 흑백 옵션이 따로 있다(학원 프린터 고려)
- 범례에 **`일반 유형` / `중요 유형`** 구분 추가 — 중요 유형은 테두리가 다르다

→ 우리 `student_node_status` 에는 `updated_at` 밖에 없어 **시점별 스냅샷을 못 만든다.**
   이 화면을 하려면 주차별 집계 테이블이 따로 필요하다. (지금은 못 함 — 설계에 반영할 것)

## 10. ★★ 과제 탭 (`/homework`) — 메꾸기 입구가 4개다

```
[단원과제 만들기]  [오답과제 만들기]  [취약과제 만들기]  [유형과제 만들기]
```

목록 칼럼: `과제명 · 단원 · 난이도 · 제출기간 · 학생 · 제출`
필터: 제목 검색 + 기간(`2026.07 ~ 2026.09`) + `전체(삭제제외)`

| 버튼 | 무엇으로 만드나 | 우리 대응 |
|---|---|---|
| **단원과제** | 진도 나간 단원 | 있음 (출제 화면) |
| **오답과제** | 학생이 틀린 문제 | **없음** ← 설계서 S4 |
| **취약과제** | 숙달 낮은 유형(γ) | **없음** ← 설계서 S6 |
| **유형과제** | 유형 직접 지정 | 부분 (유형 트리 검색) |

→ **"메꾸기"는 한 가지가 아니라 네 갈래다.** 우리 설계서는 오답(S4)만 잡고 있었는데,
   **취약과제**(틀린 적 없어도 숙달이 낮은 유형)가 별도로 있다. 이게 진짜 예방이다.

**흐름이 우리 설계와 반대다.**

| | 우리 설계 (S4/S6) | 매쓰홀릭 취약과제 |
|---|---|---|
| 시작 | 교사가 단원·유형을 고른다 | **기간만 정하면 취약유형을 시스템이 찾는다** |
| 문제 | 검색 결과에서 사람이 담는다 | **이미 뽑혀 카드로 깔려 있다** (전부 선택된 상태) |
| 교사 할 일 | 고르기 | **빼기** (체크 해제) |
| 분량 | 사람이 셈 | **유형당 1/2/3개** 로 지정 |

### 뜯어볼 점
- **`분석 기간`이 입력의 전부다** — 최근 1주(8/26~9/2)가 기본. "요즘 뭘 못하나"를 기간으로 묻는다.
- **`취약유형 5 · 선택 5`** — 찾아낸 취약유형 수와 지금 담긴 수를 하단에 항상 표시.
- 문제 카드에 **난이도 배지**(`개념` / `실력(하)`) — 같은 유형이라도 난이도를 섞어 준다.
- **`보기: 자동`** — 문제 배치/선택 방식으로 추정 (미확인).
- 3단계 스텝퍼 `취약 탐색 → 문제 편집 → 과제 설정` — 출제 라인(01~04)과 **같은 3단 골격**.

### 우리 데이터로 되는가
- 취약유형 찾기 = `student_node_status` 에서 γ/β 뽑기 → **된다**
- 기간 제한 = `last_tested_at` 으로 필터 → **된다**
- 유형당 N문제 = `classifications.type_code` prefix + `difficulty` 로 조회 → **된다**
- 난이도 섞기 = difficulty 분산 → **된다**

→ **AI 없이 지금 데이터로 이 화면을 만들 수 있다.** (S6 매트릭스보다 오히려 만들기 쉽다)

### 10-2. 오답과제 만들기 — 취약과제와 구조가 다르다

```
확률과 통계 -개념진도반 오답과제 만들기                              ✕
──────────────────────────────────────────────────────────────
 ∨ 학생 선택                                              2명
   2 / 2명 선택                                    [전체 해제]
   ☑ 김태한      ☑ 염예진
──────────────────────────────────────────────────────────────
 ∨ 단원 선택                                              0개
   ☐ 확률과 통계 (2022 개정)
     ⊟ ☐ 1 경우의 수
        ⊟ ☐ 1.1 여러 가지 순열
             ☐ 1.1.1 중복순열
             ☐ 1.1.2 같은 것이 있는 순열
──────────────────────────────────────────────────────────────
                          (단원을 1개 이상 선택해주세요)  [ 과제 생성 ✓ ]
```

| | 취약과제 | 오답과제 |
|---|---|---|
| 스텝퍼 | **3단계** (취약탐색→문제편집→과제설정) | **없음. 한 화면** |
| 범위 지정 | **분석 기간** (날짜) | **단원 트리** (체크박스) |
| 문제 미리보기 | 있음 (카드) | 없음 |
| 학생 기본값 | 0명 선택 | **2/2 전체 선택** |
| 버튼 | `2. 문제 편집 →` | `과제 생성 ✓` (바로 생성) |

→ **오답은 "이미 틀린 것"이라 고를 게 없다** → 단원만 정하면 끝, 한 화면.
   **취약은 "찾아내야" 한다** → 탐색 결과를 보여주고 편집하게 한다. 3단계.

★ 이 차이가 설계에 중요하다. 우리 S4(오답)는 간단하고, **S6(취약)이 진짜 일**이다.

## 12. ★ 정리 — 우리 설계서(PLAN_EXAM_LINE_DESIGN)에 무엇을 고쳐야 하나

### (1) "메꾸기"는 네 갈래다 — 설계서는 한 갈래만 잡고 있었다

설계서 S4 는 **오답**만 본다. 실제 운영에는 네 입구가 있고 성격이 다르다.

| 입구 | 무엇을 준다 | 언제 쓰나 | 우리 |
|---|---|---|---|
| 단원과제 | 진도 나간 단원 | 수업 직후 | 있음 |
| **오답과제** | 틀린 문제 | 시험/과제 직후 | S4 (미착수) |
| **취약과제** | **숙달 낮은 유형** | 주기적 점검 | **설계에 없음** |
| 유형과제 | 지정 유형 | 교사 판단 | 부분 |

**취약과제가 빠져 있다.** 틀린 적이 없어도 숙달이 낮은 유형이 있고, 그게 진짜 구멍이다.
오답만 보면 "안 배운 것/안 풀어본 것"을 영영 못 잡는다.

### (2) 만드는 순서를 바꿔야 한다

설계서는 `S6 매트릭스` 를 마지막에 두었는데, **취약과제는 매트릭스 없이도 만들 수 있다.**
매트릭스는 "보여주는" 화면이고, 취약과제는 "일하는" 화면이다.

권장 순서:
1. **취약과제 만들기** — `student_node_status` γ/β + 기간 → 문제 자동 선별. AI 0원. 화면 하나.
2. **오답과제** — 더 간단(단원 트리 + 학생). session_results 로 바로 됨.
3. **유형 숙달 매트릭스** — 위 둘의 결과를 눈으로 확인하는 화면. 재사용(서술형·고난도).
4. 유형이력(시간축) — **주차별 스냅샷 테이블이 없어 지금은 못 함.** 별도 설계 필요.

### (3) 지금 데이터로 되는 것 / 안 되는 것

| 기능 | 우리 데이터 | 판정 |
|---|---|---|
| 취약유형 찾기 | `student_node_status` (63명·3,950건) | **된다** |
| 기간 제한 | `last_tested_at` | **된다** |
| 유형당 N문제 뽑기 | `classifications` type_code + difficulty | **된다** |
| 난이도 4단계 축 | difficulty 1~10 → 4구간 | **된다** |
| 오답 뽑기 | `session_results.is_correct=false` | **된다** |
| **AI 예측으로 빈칸 채우기** | 없음 | ✕ (비용 드는 별건) |
| **주차별 추이 차트** | 스냅샷 테이블 없음 | ✕ (설계 필요) |

★ 다만 **문제은행 유형 분류 31,680건 미완**이 전제 조건이다.
  분류가 안 붙은 문제는 "그 유형의 문제"로 뽑히지 않는다. (헤르메스 작업 중)
