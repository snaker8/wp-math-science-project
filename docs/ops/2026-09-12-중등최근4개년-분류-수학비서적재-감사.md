## 4. ★ 수학비서 중등 자료 적재 reconciliation

### 4-1. 대조 방법 (번호·표기 차이로 누락 판정하지 않음)

- `2026-09-02` 문서의 교훈대로 **번호를 맞춰 비교하지 않았다.**
- DB 제목의 **이중 공백**(`24-3-1-F  부곡여중 수학`)을 정규화했다.
  → 이 정규화만으로 **3건이 "미적재"에서 회수**됐다 (장전중·부곡여중·해운대중).
  표기 차이를 누락으로 오판하지 않기 위한 필수 단계였다.
- 중복 삭제분은 누락에서 제외하되, **살아있는 원본이 실재하는지 건별로 확인**했다.

### 4-2. 정합 (local total = matched + duplicate-resolved + terminal failures + true missing)

**키 단위 (고유 283)**

| 구분 | 2학기(지정범위) | 1학기(범위밖) | 합계 |
|---|---:|---:|---:|
| local unique keys | 69 | 214 | **283** |
| DB matched (살아있는 원본 있음) | 64 | 187 | **251** |
| ─ 그중 duplicate-resolved 이력 있음 | 25 | 86 | 111 |
| only-deleted (살아있는 원본 없음) | 0 | 0 | **0** |
| parse/import failed (종결 실패로 기록된 것) | 0 | 0 | **0** |
| **true missing (DB에 아예 없음)** | **5** | **27** | **32** |
| 살아있는 중복 | 0 | 2 | 2 |

**파일 단위 (289)**

```
289 = 256 matched + 0 duplicate-only + 0 terminal failures + 33 true missing
      (matched 251키 + 중복파일 5)          (missing 32키 + 중복파일 1 = 해운대여중)
```

정합 ✅. **duplicate-resolved 111키는 전부 살아있는 원본이 대응**하므로 누락이 아니다
(only-deleted 0건이 이를 증명한다 — 지워지기만 하고 남은 게 없는 키는 하나도 없다).

**terminal failure 0**의 의미: 파싱·임포트 실패로 **기록된** 건이 없다는 뜻이다.
9/7 실행 리포트가 남아 있지 않으므로, 미적재 33건이 "실패했는데 조용히 넘어간 것"인지
"애초에 대상이 아니었던 것"인지는 **현재 증거로 구분할 수 없다.**

## 5. 이 감사에서 내가 한 번 틀렸던 것 (방법 기록)

1. **LEFT JOIN 미매치를 `alive=1`로 오집계.** `count(*) FILTER (WHERE ex.deleted_at IS NULL)`은
   조인 미매치 행에서도 `NULL IS NULL` = TRUE라 1로 세어진다. → `count(ex.id)`로 교정.
   이 오류 때문에 첫 대조에서 "69건 전부 정상"이라는 **거짓 PASS**가 나왔다.
2. **제목 이중 공백을 누락으로 오판.** 정규화 후 3건 회수.

→ 대조 쿼리는 **합계가 다른 경로 집계와 맞는지 교차 검증**해야 한다
(이번엔 65 vs 69 불일치가 단서였다).
