# 중복 시험지 정리 — 중등 .hml 재임포트분 (2026-09-02)

## 무슨 일이 있었나

9/1 에 수학비서 .hml 자료를 다시 임포트하면서, **이미 자산화가 끝난 중등 기출이 한 벌 더** 들어왔다.
두 벌이 같은 시험지인데 제목이 달라서 중복으로 안 보였다.

| | 기존 | 재임포트 |
|---|---|---|
| 생성 | 2026-04~08 | 2026-09-01 |
| 경로 | OCR (Mathpix) | .hml 직접 파싱 |
| 제목 | `25-2-1-F 여명중 수학` | `25-2-1-F 여명중 중등수학2상` |
| 상태 | 유형분류 완료 · 검수됨 | 분류 미완료 |

제목이 갈린 이유는 `scripts/import-mathsecr.ts` 의 `buildTitle` 이 파일명 끝 교과서명을
그대로 붙이기 때문. 앞의 `25-2-1-F` 가 이미 학년·학기를 말하므로 중복 표기다.

## 판정 방법 (문항 수만으로는 부족)

본문 md5 로는 49쌍 중 6쌍만 일치했다. OCR 과 .hml 은 같은 문제라도 LaTeX 표기가 다르다.
그래서 **한글만 남긴 지문의 앞 20자**로 교집합을 셌다.

```sql
left(regexp_replace(content_latex, '[^가-힣]', '', 'g'), 20)
```

같은 학교·연도·학기·중간/기말 + 문항 수 동일 + 지문 90% 이상 일치 → 중복 확정.

## 2차 — 보류 12건 (같은 날 처리)

`[서논술형3]` 같은 **OCR 머리표를 본문에서 걷어내고** 다시 세니 일치율이 확 올랐다
(온천중 22/22, 해강중 20/21, 동백중 20/23 …). 동백중을 1~24번 눈으로 대조해 같은 시험지임을
확인했고, 12건 전부 재임포트분을 삭제했다. **시험지 12 · 문항 264.**

> 교훈: 지문 비교 전에 `\[[^\]]{0,20}\]` (대괄호 머리표)와 이미지 링크를 지워야 한다.
> 안 지우면 같은 시험이 50%대로 나온다.

## 3차 — 이번 건과 무관한 옛 중복 (69쌍 → 64건 삭제)

같은 학교·연도·학년·학기·회차인데 제목 표기만 다른 것들. `공통수학1`=`수학상`,
`수학(하)`=`수학하`, `거제여중`=`거제여중 수학` 등. 남길 쪽은 **분류된 문항이 많은 쪽 →
문항 많은 쪽 → 먼저 만들어진 쪽** 순으로 정했다.

| 기준 | 건수 |
|---|---|
| 일치율 90%+ · 문항수 차 ≤2 · 양쪽 10문항 이상 | 51 |
| 파편(문항 ≤6, 상대는 15+) — 실패한 부분 임포트 | 8 |
| 부분집합(작은 쪽 문항의 90%+ 가 큰 쪽에 있음) | 5 |
| **보류** | 3 |

**★ 여기서 지우면 안 되는 것 세 종류를 걸러냈다** (실수 방지):
1. `23-1-2-F 세종과학고 심화수학1A` vs `1B` — **다른 시험지**(일치율 0%). `형` 없이 뒤에 붙는
   A/B 도 변형 표시로 봐야 한다 → 가드에도 `tail_ab` 로 반영.
2. `25-3-1-F 학장중`(exam_year=**2026**) vs `26-3-1-F 학장중 수학` — **연도 컬럼이 틀려서**
   다른 연도 시험이 한 그룹에 묶였다. 제목 연도를 직접 읽도록 바꿔 분리했고, 컬럼도 2025 로 고쳤다.
   (전체 스캔 결과 이 1건뿐)
3. 문항 1~6개짜리 **파편** — 일치율이 4~22% 로 낮게 나오지만 내용이 다른 게 아니라 임포트가
   깨진 것. 일치율만 보면 "다른 시험"으로 오판한다.

## ★ 정정 (2026-09-03) — 대조 방법이 틀렸다, 그리고 더 큰 걸 찾았다

대표가 대조표에서 "같은 8번인데 문제가 다르다"를 짚었다. 확인해 보니
**문제가 다른 게 아니라 번호가 달랐다.**

```
신도중 '호수 둘레' 문제 →  기존 8번 · 재임포트 16번   (같은 문제)
```

대조표를 **번호를 맞춰** 만들어서, 순서만 다른 시험지가 "다른 시험지"로 보였다.
순서를 무시하고 다시 세니 신도중은 11/20 → **18/20**, 사직중은 18/21 → **20/21**.

### 왜 순서가 다른가 — 두 경로가 번호를 다르게 매긴다

| | 번호를 어디서 얻나 |
|---|---|
| OCR 업로드 | **시험지에 인쇄된 번호를 읽는다** (`upload/route.ts` `edited.number`) |
| .hml 가져오기 | **파일 안 등장 순서대로 1,2,3…** (`hml-parser` 의 `n += 1`) |

원본 .hml 을 열어 확인했다 — 수학비서 `내문제지` 파일에는 **문항 번호가 아예 없다.**
`[출처]`·`[정답]`·`[해설]` 블록만 있고 문제들이 수학비서가 담은 순서로 들어 있다.
파일 안 순서: `몇배 … 이웃 … 완전제곱 … 호수` = 재임포트분의 6·8·14·16 과 정확히 일치.

→ **기존(OCR)이 시험지에 인쇄된 번호다.** 재임포트분의 번호는 시험지와 무관하다.
   그걸로 정답표를 만들거나 QR 채점을 하면 답이 밀린다. (대표 지적: *"순서가 다르면
   안되지 답이 다를건데"*)

### 처리

되돌렸다가(12건) 다시 정리했다 — **기존을 남기고 재임포트분 10건 삭제**
(표시 시각 `2026-09-03 10:00:00+00`, 문항 222).
**센텀중 2건은 제외** — 순서를 무시해도 10/21·12/20 만 겹쳐 내용 자체가 다르다. 판단 대기.

### 남은 진짜 문제 (미해결)

**.hml 로 들어온 시험지는 원본 문항 번호를 알 수 없다.** 지금은 그걸 모른 채 1,2,3 을
붙여 저장한다. 학교 원본 시험지와 대조하거나 정답표를 맞출 때 어긋나는데, 화면 어디에도
그 사실이 안 보인다. 최소한 "원본 번호 불명" 표시가 필요하다. (대표 확인 대기)
