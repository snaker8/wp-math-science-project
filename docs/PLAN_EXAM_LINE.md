# 출제·학습 루프 설계 (2026-08-29)

> 작성 배경: 출제 화면이 6개(6,700줄)로 흩어져 있고 어느 것도 끝까지 이어지지 않는다.
> "하나씩 필요할 때마다 구현"한 결과. 이번엔 **제대로 된 하나**를 세운다.

## 0. 우리의 강점 (설계의 중심축)

**내신 기출로 학생을 진단하고 추적해서 약점을 메꾼다.**

매쓰홀릭은 전국 10만 기출 DB가 강점이지만, 우리는 **그 학교 기출로 그 학생을 추적**하는 정밀도로 간다.
- 학교기출 141건 자산화 · 문제 6,185건 (출처 100% 보유: 학교·연도·중간/기말)
- 수학비서 유형 2,573종으로 분류 (95% 완료)
- 진단 숙달 3,950건 (α/β/γ), QR 채점 1,658건

## 1. 목표 루프 (닫혀야 할 한 바퀴)

```
[내신 기출 자산화] ✅ 완성 — 공들인 라인, 건드리지 않는다
        ↓ 유형 추출
[출제] ①기출 원본 ②시중교재 유사 ③AI 변형(숫자·조건)     ← 만들 것 A
        ↓
[인쇄] ✅ 완성 (2단·배점 자동분배·한글·헤더)   [온라인 배포] ← 만들 것 A-2
        ↓                                          ↓
[QR 채점] ✅ 있음                    [학생이 풀고 답 입력] ← 만들 것 B
        ↘                                        ↙
            [성취도·오답 분석 / 유형 숙달 매트릭스]   ← 만들 것 C
                        ↓
            [약점 유형 → 다시 출제로]  = 메꾸기 루프
```

## 2. 문제 공급원 3갈래 (출제의 핵심)

| 공급원 | 현재 | 비고 |
|---|---|---|
| ① 기출 원본 | ✅ 6,185건 | 학교·연도·시기 100% |
| ② 시중교재 유사 | 🟡 시중교재 자산화 1건 | **앞으로 축적** — 자산화 계속하면 쌓임 |
| ③ AI 변형 | ✅ `lib/workflow/twin-generator.ts` | LaTeX 숫자/조건 변형 구현됨. 출제 화면에 미연결 |

## 3. 현재 위치 (판단이 아니라 순서 정하기용)

### 완성 — 유지
- 자산화(HWP/PDF→OCR→분해→분류), 인쇄(ExamPaperView 2단·배점·한글·헤더 5종), QR 채점

### 흩어짐 — 통합 대상 (6화면 6,700줄)
| 경로 | 줄 | 성격 |
|---|---|---|
| `/dashboard/create` | 1,646 | 단원→유형→문항수. "시험지 출제" |
| `/dashboard/exam-create` | 2,163 | 소스탭·필터·선택트레이. **메뉴에 없음** |
| `/dashboard/exam-management` | 1,562 | 저장소+A4 미리보기+인쇄. **실제 동작 확인됨** |
| `/dashboard/similar` | 711 | 출판교재 유사 |
| `/dashboard/cloud/create-exam` | 346 | 선택 문제로 시험지 |
| `/dashboard/curation` | 279 | AI 자동 출제 |

★ create 와 exam-create 는 **화면 제목이 둘 다 "시험지 출제"**.

### 비어 있음 — 만들 것
- **A. 출제 화면 하나** — 소스 선택 → 유형/난이도 선택(분포 카운터) → 3공급원 배합 → 편성 → 인쇄 라인으로 인계
- **B. 학생 풀이 화면** — `/student/solve/[id]` 가 12줄 껍데기. 제출 API(`/api/session-results/from-student`)는 이미 존재
- **C. 유형 숙달 매트릭스** — 데이터 3,950건 있는데 볼 화면 없음. 행=소단원 × 열=난이도, 약점 → 출제 원클릭

## 5. 원칙

1. **되고 안 되고로 미리 자르지 않는다** — 목표를 먼저 그리고 순서를 정한다. 데이터가 없으면 채우는 것도 계획에 포함.
2. **자산화·인쇄 라인은 건드리지 않는다** — 공들여 완성된 곳.
3. 기존 화면은 즉시 삭제하지 않는다 — 새 화면이 안정된 뒤 정리.
4. 운영에 지장 없게: 워크트리 작업 → 빌드·타입 검증 → 육안 확인 → 배포.
